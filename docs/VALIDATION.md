# Статус проверки

## Исходный Windows CPU сценарий, 9 октября 2026

Настоящий checkpoint VGGT-1B, CPU PyTorch 2.7.1, dynamic INT8 для 308 Linear-слоёв,
Python 3.12, Rerun 0.23.4. ROS Noetic запускался в Docker Desktop на x86_64.

- Два кадра 280 × 154, 66 080 точек.
- Инференс 4,16 с; от начала bag до облака 7,56 с.
- Полный тест с подготовкой модели и ROS — 44,27 с.
- Пик рабочего набора worker с дочерними процессами — 1,69 GiB, без Docker и Viewer.
- Координаты и цвета ROS PointCloud2 точно совпали с выходом модели; проверены stamp и frame_id.
- Кеш и тестовый ответ вместо нейросети не использованы.
- Настоящая сцена визуально просмотрена в Rerun.

[Машиночитаемый отчёт без локальных путей](windows-cpu-result.json).
Он относится к исходному live_vggt_ros1 до добавления CUDA и подготовки экспорта.

Обычный FP32 на этом ноутбуке не завершён из-за нехватки памяти. Точность по ground
truth и отличие INT8 от FP32 не измерены. В облаке есть искажения; confidence
в INT8-прогоне выродилась в 1,0. Совпадение публикации с выходом модели доказывает
правильность передачи данных, а не качество восстановления сцены.

## Jetson Thor

CUDA-путь и контейнер подготовлены **без доступа к Thor**. Нет измерений скорости,
памяти или качества на устройстве. Наличие ARM64 в manifest ROS-образа проверено;
оно не заменяет сборку и запуск на ARM64. Начните с проверки CUDA по инструкции.

## Проверки экспортированного репозитория, 9 октября 2026

- Самостоятельный Dockerfile ROS собран на x86_64; catkin-пакет успешно собран заново.
- `tests/ros_smoke.py` прошёл на реальном входном bag с явно заданным тестовым
  ответом вместо нейросети: проверены timestamps, отбрасывание NaN, XYZ/RGBA.
- Проверены направление преобразования камеры, выбор конечных точек положительной
  глубины и создание модели без выделения памяти под параметры.
- Четыре теста `tests/test_device_guards.py` прошли: отсутствие CUDA, несовместимость
  CUDA с CPU INT8, неподдерживаемый BF16, отказ при низкой доступной RAM.
- Compose-конфигурация, синтаксис Bash/Python и локальные ссылки документации проверены.

Повторный полный инференс после добавления CUDA здесь не выполнен: на ноутбуке
снова недостаточно свободной RAM. Приведённые выше числа относятся к ранее
проверенному исходному CPU-сценарию. Тесты ошибок используют моки и не подтверждают
вычисления на CUDA.
